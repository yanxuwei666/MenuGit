## 1. 项目概述

### 1.1 背景与问题

日常 Git 操作需要记忆命令和理解仓库状态。目标用户希望从文件管理器完成常用操作，减少终端和独立客户端之间的切换。原需求认为现有方案在平台覆盖、体量或使用复杂度上存在不足；这些判断尚缺竞品研究证据，列为假设 A1。

### 1.2 产品定位与目标

- **产品定位：**面向桌面 Git 用户的轻量跨平台工具，通过文件管理器右键菜单完成常用操作。
- **核心价值：**在文件上下文中查看状态和差异，完成常见 Git 操作，并复用系统已有配置与凭证。
- **项目目标：**完成“修改 → 提交 → 推送”而无需打开终端；支持在普通目录初始化或克隆仓库。原文希望安装后无需配置即可使用全部 P0 功能，实际仍依赖系统 Git、身份、网络与远端凭证，适用条件待确认（Q6）。

### 1.3 现有方案与产品差异

| 产品或解决方式 | 主要特点 | 不足与机会 | 资料来源 |
| --- | --- | --- | --- |
| 命令行 Git | 通过命令完成仓库操作 | 用户需要记忆命令；具体用户影响待验证 | 原 v0.3 需求 |
| 图形客户端、文件管理器 Git 集成 | 提供图形界面或文件管理器入口 | 三端覆盖、操作体验及轻量程度的比较待调研（A1） | 竞品资料待补充 |

### 1.4 项目范围与约束

| 类别 | 内容及说明 |
| --- | --- |
| 本版包含 | P0：右键菜单、提交与差异、拉取、推送、分支、日志、放弃修改、冲突解决、初始化、克隆和设置（FR-01～FR-11）。 |
| 后续考虑 | P1：状态角标、更多 Linux 文件管理器、stash、分支重命名/删除、标签和忽略文件管理、行级暂存、日志分支图、图片差异。 |
| 明确不做 | 强制推送、交互式 rebase、cherry-pick、子模块管理、Git hook 管理、内置终端、多仓库批量管理、MenuGit 自有账号或凭证存储、设置页中的 Git 配置项。 |
| 约束与依赖 | 目标为 Windows、macOS、Ubuntu 24.04；依赖系统文件管理器和 Git 命令。首发顺序与具体范围见 Q1、Q5。系统 Git 配置与凭证的边界见 BR-02 和 Q7。 |

## 3. 业务流程与规则

### 3.1 主要场景与流程

| 场景 | 角色与触发条件 | 主要步骤 | 预期结果 | 异常或分支 | 关联功能 |
| --- | --- | --- | --- | --- | --- |
| 日常提交与推送 | 用户在仓库目录或文件上右键 | 查看改动和差异 → 选择文件并提交 → 确认推送 | 本地提交产生并收到推送反馈 | 推送取消或被拒时按功能规则处理 | FR-01、FR-02、FR-04 |
| 拉取和冲突处理 | 用户在仓库中发起拉取 | 选择来源 → 拉取 → 有冲突时逐项处理 | 拉取成功，或冲突完成合并 / 中止 | 认证和网络失败可重试 | FR-03、FR-08 |
| 创建或获取仓库 | 用户在非仓库目录右键 | 初始化目录或输入地址并克隆 | 新仓库可在文件管理器中使用 | 目标非空、网络或认证失败 | FR-09、FR-10 |

**菜单形态矩阵**

右键菜单内容只由一个条件决定：右键目标是否位于某个 Git 仓库内（发现规则见 BR-01）。文件级右键复用同一组菜单，仅预置该文件的上下文。

| 右键目标 | 菜单内容 | 说明 |
| --- | --- | --- |
| 仓库内目录/文件 | 提交、拉取、推送、分支、日志、放弃修改、解决冲突 + 设置 | 操作作用于所属仓库根；文件级右键时提交窗口预选该文件、日志按该文件过滤 |
| 非仓库目录 | 在此初始化 Git 仓库、克隆仓库到此处 + 设置 | 入口操作，让新用户可从零开始 |
| 仓库内，但 git 命令不可用 | 同仓库菜单，点击任意项提示"未检测到 Git" | 提示含各平台安装指引，见 BR-02 |

菜单项规则：

- 任何时刻用户看到的菜单不超过 7+1 项（仓库内）或 2+1 项（非仓库）。
- "解决冲突"在仓库菜单中常驻，**无冲突时置灰**，存在冲突时高亮。
- "设置"位于分隔线之后的最底部，两个场景均可见。
- 只显示与当前场景相关的项，不显示灰色的不可用占位项（"解决冲突"除外，它承担冲突状态提示职责）。

**菜单示意**

```
仓库内右键 → MenuGit ▸                    非仓库右键 → MenuGit ▸
    提交…    ◄─ 主窗口：状态+差异+提交         在此初始化 Git 仓库
    拉取                                      克隆仓库到此处…
    推送                                  ─────────────
    分支…    ◄─ 创建 / 切换                   设置…
    日志…
    放弃修改…  ◄─ 二次确认
    解决冲突…   ◄─ 无冲突时置灰
─────────────
    设置…
```

**提交窗口示意**

MenuGit 只有一个日常主窗口：打开即状态，点文件即差异，填信息即提交。

```
┌ 提交 · my-project ── 分支 main（领先 origin/main 1 个提交）─ ✕ ┐
│                                                              │
│  [×] 修改    src/app.py                          +24 −6      │
│  [×] 新增    src/utils.py                                    │
│  [×] 删除    docs/old.md                                     │
│  [ ] 未跟踪  notes.txt                                       │
│  ──────────────────────────────────────────────              │
│  （点击文件名，此处显示该文件的差异预览）                           │
│  ──────────────────────────────────────────────              │
│  提交信息（必填）…                                             │
│                                                              │
│  作者：yxw <yxw@example.com>（来自系统 Git 配置）  [取消] [提交 3 个文件] │
└──────────────────────────────────────────────────────────────┘
```

工作区干净时同一窗口显示空状态："工作区干净，与 origin/main 同步（或 领先 n / 落后 n）"。


### 3.2 共享业务规则

- **BR-01 仓库发现**：从右键目标所在目录起向上逐级查找 `.git`；找到则进入"仓库菜单"，所有操作作用于该仓库根，窗口标题展示仓库根与当前分支；未找到则展示"入口菜单"（FR-09 / FR-10）。
- **BR-02 配置与凭证**：MenuGit 只读复用系统 Git 的全部配置（user.name/email、credential helper、ssh-agent、代理、pull 策略等），不修改用户任何 Git 配置，不存储账号凭证；自身仅保存 FR-11 中的设置项与界面偏好（窗口尺寸、最近过滤词）。git 命令不可用时：菜单仍可见，点击后提示"未检测到 Git"，并展示对应平台的安装指引 【待确认：Q3】。
- **BR-03 并发锁**：同一仓库同一时刻只允许一个写操作（提交 / 拉取 / 推送 / 切换分支 / 放弃修改 / 克隆写入 / 冲突解决提交）进行，后到的写操作提示"正在执行其他操作"；读操作（状态 / 差异 / 日志）随时可用。
- **BR-04 破坏性操作确认**：P0 中的破坏性操作是"放弃修改"（FR-07）与"中止合并"（FR-08）：确认框必须明确说明影响范围（哪些文件、什么后果）且需点击确认按钮生效。
- **BR-05 错误呈现**：所有 Git 报错统一转换为一句可读原因（如"远端拒绝了推送：远端有你没有的提交"），并提供"显示详细信息"展开 Git 原始输出，便于求助与排障。
- **BR-06 操作反馈**：写操作在触发窗口内即时反馈结果（成功摘要或错误），不弹系统级通知、不播放音效；进行中的操作在窗口与菜单处显示"进行中"状态。
- **BR-07 界面语言**：默认跟随系统语言，可在设置（FR-11）中固定为中文或英文；首发提供中文与英文。

### 4.2 右键菜单集成 `P0`

#### FR-01 右键菜单集成

- **目标与角色**：桌面 Git 用户；让用户在任何仓库路径下一步触达全部常用操作，无需打开应用。
- **适用平台与范围**：Windows、macOS、Ubuntu 24.04；各平台首发顺序及文件管理器范围待确认（Q1、Q5）。
- **前置条件与入口**：用户在受支持的文件管理器（Windows 资源管理器、macOS Finder、Linux GNOME Files 【待确认：Q1、Q5】）中右键点击文件或目录。
- **处理规则**：
  - 所有功能收纳在右键"MenuGit"子菜单中，形态见 3.1 菜单形态。
  - 按 BR-01 仓库发现规则决定展示"仓库菜单"还是"入口菜单"。
  - 仓库菜单顺序固定：提交 / 拉取 / 推送 / 分支 / 日志 / 放弃修改 / 解决冲突 / — / 设置。
  - 文件级右键：打开提交窗口时预勾选该文件；打开日志时按该文件过滤。
  - 子目录右键的操作作用于所属仓库根，窗口标题中展示仓库根路径与当前分支。
- **结果与状态变化**：点击菜单项打开对应窗口（FR-02、FR-05、FR-06、FR-07、FR-08、FR-09、FR-10、FR-11）或直接执行（拉取/推送，FR-03/FR-04）。
- **异常**：git 命令不可用时按 BR-02 处理；文件管理器扩展安装/启用失败时，安装器需给出重新启用指引。
- **验收条件**：在受支持的文件管理器中，仓库和非仓库目标显示对应菜单；文件右键将文件上下文传入提交和日志。

### 4.3 提交（主窗口：状态 + 差异 + 提交） `P0`

#### FR-02 提交（主窗口：状态 + 差异 + 提交）

- **目标与角色**：桌面 Git 用户；把"看状态、看差异、提交"合成一个窗口，用户要学的只有一个界面。
- **适用平台与范围**：Windows、macOS、Ubuntu 24.04；各平台首发顺序及文件管理器范围待确认（Q1、Q5）。
- **前置条件与入口**：仓库内右键 → "提交…"。
- **处理规则**：
  - 窗口内容见 3.1 提交窗口示意：顶部状态条（当前分支、上游、领先/落后提交数）、变更文件列表（勾选 = 暂存）、差异预览区（点击文件展开）、提交信息输入、作者信息展示。
  - 顶部分支徽章可点击，直接打开分支窗口（FR-05）切换或新建本地分支；提交始终落在当前分支上，"把改动放到新分支"应在提交前完成分支切换。
  - 变更文件按状态标记：`新增` `修改` `删除` `未跟踪` `冲突`，重命名显示"旧名 → 新名"；列表支持按文件名过滤。
  - 默认勾选规则：**修改、删除、重命名的文件默认勾选；新增/未跟踪文件默认不勾选**（防止误提交杂物）。"新增是否默认勾选"可在设置中反转（FR-11）。
  - **差异预览（共享视图，日志详情复用同一规格）**：位于文件列表右侧的固定预览区，点文件名即显示该文件 diff（左右两栏各自滚动）；只读、增/删行高亮；二进制文件显示元信息并提示"不支持内容对比"；文件编码异常时按字节展示并提示；文件过大时只加载前 N 行并提示 【待确认：Q8】。
  - 提交信息必填；首行超过 50 字符时软提示（不阻止提交）。支持多行信息。
  - 作者身份直接取系统 Git 配置的 user.name / user.email 并在窗口展示；不在窗口内提供修改入口（提示用户修改系统 Git 配置，见 BR-02）。
  - 提交完成后窗口保留并刷新为新的变更列表，可直接继续下一次提交。
- **结果与状态变化**：产生一个本地提交；顶部计数变为"领先上游 n"；文件从未暂存/暂存区移除；随后**自动打开推送面板**（FR-04）。推送面板取消后：若工作区仍有未提交变更，返回提交窗口继续处理；若已全部提交，直接结束流程回到文件管理器，不再显示空提交窗口。
- **异常**：
  - 工作区干净：显示空状态（见 3.1 提交窗口示意），提交按钮禁用。
  - 未勾选任何文件或信息为空：提交按钮禁用并提示原因。
  - pre-commit 等 hook 执行失败：展示 hook 输出，本次提交不生效，用户可修改后重试。
  - 存在冲突文件：冲突文件不可勾选，顶部提示先处理冲突（FR-08）。
- **验收条件**：选择变更并填写提交信息后产生本地提交并进入推送流程；未选择文件、信息为空及冲突文件均按规则处理。

### 4.4 拉取 `P0`

#### FR-03 拉取

- **目标与角色**：桌面 Git 用户；把远端更新合入当前分支。
- **适用平台与范围**：Windows、macOS、Ubuntu 24.04；各平台首发顺序及文件管理器范围待确认（Q1、Q5）。
- **前置条件与入口**：仓库内右键 → "拉取"，打开拉取对话框（与推送对话框同构：本地分支 + 来源远端/分支），确认后执行。
- **处理规则**：
  - 对话框默认来源为当前分支的上游，一次确认即完成；可改从其他远端分支拉取（下拉建议来自该远端已有分支）。
  - 执行期间显示进行中状态；遵循 BR-03 并发锁。
  - 当前分支无上游时：对话框同处选择来源分支，执行并记住上游设置（--set-upstream）。
  - 合并行为完全遵循用户系统 Git 配置中的 pull 策略，MenuGit 不额外干预。
  - 产生冲突时进入 FR-08 冲突处理。
- **结果与状态变化**：成功后显示摘要："拉入 n 个提交，更新 m 个文件"；无更新时显示"已是最新"。
- **异常**：认证失败 / 仓库不可达 / 网络错误：按 BR-05 呈现可读原因与原始输出，提供"重试"。
- **验收条件**：选择来源并确认后执行拉取，展示成功、无更新或可恢复的失败结果；冲突进入冲突处理。

### 4.5 推送 `P0`

#### FR-04 推送

- **目标与角色**：桌面 Git 用户；把本地提交发布到远端。
- **适用平台与范围**：Windows、macOS、Ubuntu 24.04；各平台首发顺序及文件管理器范围待确认（Q1、Q5）。
- **前置条件与入口**：仓库内右键 → "推送"；或提交（FR-02）完成后自动打开。
- **处理规则**：
  - 推送打开轻量目标面板（参考 TortoiseGit 但极简）：默认目标为当前分支的上游，一次确认即完成；可改推到其他远端分支（下拉建议来自该远端已有分支）。
  - 目标输入新名称时在远端新建分支：明确提示"将创建远端分支 origin/&lt;name&gt; 并设为上游"后执行；无上游时同 FR-03 设置跟踪。
  - 推送面板只决定远端目标名称，不改变提交所属的本地分支；从提交窗口发起推送时，取消面板可无损返回提交窗口（勾选、过滤、提交信息均保留）。
  - **不提供强制推送**（见 1.4“明确不做”）。
- **结果与状态变化**：成功反馈"已推送到 origin/main"；领先计数归零；提交窗口顶部转为"已同步"。
- **异常**：推送被拒（远端有本地没有的提交）时提示"远端有新提交，请先拉取"，并提供"立即拉取"入口；认证/网络错误同 FR-03。
- **验收条件**：确认推送目标后展示推送结果；远端拒绝时提示先拉取，取消行为按待确认项处理。

### 4.6 分支（创建 / 切换） `P0`

#### FR-05 分支（创建 / 切换）

- **目标与角色**：桌面 Git 用户；查看与切换本地分支，或从当前位置新建分支。
- **适用平台与范围**：Windows、macOS、Ubuntu 24.04；各平台首发顺序及文件管理器范围待确认（Q1、Q5）。
- **前置条件与入口**：仓库内右键 → "分支…"。
- **处理规则**：
  - 窗口列出本地分支（当前分支置顶并标记"当前"），支持按名称过滤。
  - 折叠区展示远端分支；点击远端分支 = 检出为同名本地分支并建立跟踪。
  - 窗口内提供"新建分支"输入：基于当前 HEAD 创建并立即切换。
  - 切换时未提交修改的处理遵循 Git 原生行为：能携带则携带到目标分支；Git 报告会覆盖未提交修改时阻止切换，提示"请先提交或（P1）暂存修改"，并列出受影响文件。
- **结果与状态变化**：当前分支更新；提交窗口等后续界面同步刷新。
- **异常**：分支名非法（含空格/特殊字符）时即时校验提示；切换目标分支不存在时提示并刷新列表。
- **验收条件**：用户可以创建或切换分支；会覆盖未提交修改时阻止切换并说明受影响文件。

### 4.7 日志 `P0`

#### FR-06 日志

- **目标与角色**：桌面 Git 用户；浏览提交历史并下钻到任意提交的变更。
- **适用平台与范围**：Windows、macOS、Ubuntu 24.04；各平台首发顺序及文件管理器范围待确认（Q1、Q5）。
- **前置条件与入口**：仓库内右键 → "日志…"。
- **处理规则**：
  - 列表项展示：短 hash、信息首行、作者、相对时间、"HEAD / 本地分支 / 上游"标记。
  - 默认显示当前分支历史；提供"所有分支"开关。
  - 顶部过滤框按提交信息或作者实时过滤。
  - 点击提交展开详情：完整提交信息、变更文件列表；点击文件查看该提交的差异（复用 FR-02 的差异视图规格，对比对象为该提交与其父提交）。
  - 分页加载：默认加载最近 200 条，滚动到底自动追加 【待确认：Q8】。分支图形线为 P1。
- **结果与状态变化**：只读。
- **异常**：空仓库（无任何提交）显示空状态："还没有提交，去完成第一次提交吧"。
- **验收条件**：用户可浏览提交历史、过滤并查看提交差异；空仓库显示空状态。

### 4.8 放弃修改 `P0`

#### FR-07 放弃修改

- **目标与角色**：桌面 Git 用户；把改废了的未提交修改还原，是日常防呆兜底，避免用户为此打开终端。
- **适用平台与范围**：Windows、macOS、Ubuntu 24.04；各平台首发顺序及文件管理器范围待确认（Q1、Q5）。
- **前置条件与入口**：仓库内右键 → "放弃修改…"。
- **处理规则**：
  - 窗口列出所有可放弃的变更：已跟踪文件的修改/删除（还原到 HEAD）与未跟踪文件（删除文件），每类用状态标记区分。
  - 支持全选或按文件勾选；默认不勾选任何文件，用户必须主动选择。
  - 按 BR-04 执行二次确认：确认框明确列出将影响的文件数，并写明"将永久丢弃这些修改，不可恢复"；未跟踪文件的删除需单独说明"文件将被彻底删除"。
- **结果与状态变化**：勾选文件还原或删除；列表刷新；受影响文件从变更列表消失。
- **异常**：工作区干净时点击菜单提示"没有可放弃的修改"；操作失败按 BR-05 呈现。
- **验收条件**：用户主动选择文件并确认影响后才能放弃修改；未跟踪文件删除须明确提示。

### 4.9 解决冲突（拉取后） `P0`

#### FR-08 解决冲突（拉取后）

- **目标与角色**：桌面 Git 用户；拉取产生冲突时，用最小的概念成本让用户安全走完合并，或安全退出。
- **适用平台与范围**：Windows、macOS、Ubuntu 24.04；各平台首发顺序及文件管理器范围待确认（Q1、Q5）。
- **前置条件与入口**：FR-03 拉取产生冲突时自动弹出；也可通过仓库菜单"解决冲突…"进入（无冲突时置灰）。
- **处理规则**：
  - 冲突面板列出全部冲突文件（`冲突` 标记），并统计"已解决 / 总数"。
  - 点击文件进入**内置合并编辑器**（参考 TortoiseGit 的冲突编辑，简化为网页内嵌）：每个冲突块左右并列展示"你的（当前分支）"与"传入的（origin/分支）"两个版本，用户为每个冲突块三选一——**采用本地 / 采用远端 / 保留双方**；下方实时预览该文件的合并结果。
  - 一个文件的所有冲突块都做出选择后，该文件**自动标记为已解决**（已解决文件可"重新编辑"改选）；无需用户手工编辑冲突标记文本，全程不出现 `<<<<<<<` 等标记。
  - 全部文件解决后主按钮"完成合并提交"生效，提交信息自动生成（"Merge branch …"）。
  - 任意时刻可点击"中止合并"：按 BR-04 二次确认后恢复到拉取前状态。
  - 冲突未全部解决前，仓库处于 BR-03 写锁状态，其他写操作（提交/推送/切换/放弃修改）提示"请先完成或中止本次合并"。
  - 【待确认：Q10】更复杂的冲突（如需手动混合编辑双方内容）首版不支持，提示"请在命令行处理"并给出指引。
- **结果与状态变化**："完成合并提交"产生合并提交，冲突状态解除，菜单项回到置灰；"中止合并"回到拉取前的工作区与分支状态。
- **异常**：解决过程中再次拉取/推送被 BR-03 阻止；标记已解决后又有新冲突（极少数）时刷新面板并重新统计。
- **验收条件**：用户逐块选择解决方式后可完成合并，或确认中止合并；未解决期间按规则限制其他写操作。

### 4.10 初始化仓库 `P0`

#### FR-09 初始化仓库

- **目标与角色**：桌面 Git 用户；把任意本地目录变成 Git 仓库，是新用户的入口之一。
- **适用平台与范围**：Windows、macOS、Ubuntu 24.04；各平台首发顺序及文件管理器范围待确认（Q1、Q5）。
- **前置条件与入口**：非仓库目录右键 → "在此初始化 Git 仓库"。
- **处理规则**：确认框展示目标目录名，确认后执行初始化；若系统 Git 配置缺少 user.name / user.email，提示"提交前请在系统 Git 配置中设置身份"并给出说明链接。
- **结果与状态变化**：成功后反馈"仓库已创建"，该目录右键菜单随即变为仓库菜单。
- **异常**：目标目录已是仓库（含位于仓库内部）时提示"此处已在仓库 xxx 中"，不执行。
- **验收条件**：对非仓库目录确认初始化后创建仓库；已经处于仓库时阻止操作。

### 4.11 克隆仓库 `P0`

#### FR-10 克隆仓库

- **目标与角色**：桌面 Git 用户；从 URL 获取远端仓库到本地。
- **适用平台与范围**：Windows、macOS、Ubuntu 24.04；各平台首发顺序及文件管理器范围待确认（Q1、Q5）。
- **前置条件与入口**：非仓库目录右键 → "克隆仓库到此处…"。
- **处理规则**：
  - 输入项：仓库 URL（必填，支持 https / ssh 形式）、目标文件夹名（默认取 URL 末段）、父目录（默认右键目录）。
  - 凭证完全走系统配置（credential helper / ssh-agent，见 BR-02），MenuGit 不询问、不保存账号密码。
  - 克隆过程中显示进行中状态；大仓库允许取消。
- **结果与状态变化**：成功后显示"克隆完成"，并提供"打开文件夹"按钮直达新目录。
- **异常**：目标文件夹已存在并非空 → 阻止并提示；认证失败 → 提示"请先在系统凭证/SSH 中配置访问权限"并展开原始输出；URL 无法解析 / 仓库不存在 / 网络错误 → 可读原因 + 重试。
- **验收条件**：输入有效地址并选择目标后可以克隆；目标非空、认证和网络问题展示对应反馈。

### 4.12 设置 `P0`

#### FR-11 设置

- **目标与角色**：桌面 Git 用户；为语言、排障提供兜底入口；保持概念负担为零，设置页永远不膨胀。
- **适用平台与范围**：Windows、macOS、Ubuntu 24.04；各平台首发顺序及文件管理器范围待确认（Q1、Q5）。
- **前置条件与入口**：右键菜单 → 分隔线下"设置…"（仓库内与非仓库场景均可见）。
- **处理规则**：设置页只包含 4 项：
  | 设置项 | 说明 |
  | --- | --- |
  | 语言 | 跟随系统（默认）/ 中文 / English |
  | 新增文件默认是否勾选 | 反转 FR-02 的默认勾选规则（默认：不勾选） |
  | 打开诊断日志 | 查看运行日志与 git 检测结果，排障用 |
  | 关于 | 版本号、检查更新、项目主页 |
- **边界（不放进设置）**：用户名/邮箱、代理、凭证、默认编辑器、diff 工具等一切 git config 类配置——设置页只提供"如何在系统 Git 配置中修改"的指引链接，不做输入框（见 BR-02）。
- **结果与状态变化**：全部选项即时生效，保存在 MenuGit 自身偏好中（见 BR-02）。
- **异常**：无特殊异常；诊断日志目录不可写时提示原因。
- **验收条件**：用户可使用四项设置或入口；偏好即时生效，诊断日志不可写时给出提示。
