本文是 macOS 首版的详细需求基线。[PRD](PRD-MenuGit.md) 为概要，原型用于表达已确认的页面和交互，不能证明真实 Git 或 Finder 行为已实现。尚未确定的问题和技术验证项见第 7 节；如原型模拟与本规格不一致，以本文为准并记录差异。

## 1. 产品目标与定位

- **产品目标：**让日常使用 Git 的个人开发者从 Finder 右键进入 MenuGit，在图形界面完成常见仓库操作。
- **交互方向：**借鉴 TortoiseGit 的文件上下文菜单和常见 Git 工作流，按 macOS 桌面应用的方式呈现页面与控件。
- **首发平台：**macOS。首发不支持 Windows 或 Linux。
- **首发架构：**SwiftUI / Swift 主应用、Finder Sync 扩展、系统 Git 命令行。
- **目标设备：**Apple Silicon 和 Intel Mac；Intel 兼容范围最高到 macOS 26。最低 macOS 版本在技术验证后确定。

## 2. 首发范围

### 2.1 包含

- Finder 右键菜单集成：仓库内操作，以及非仓库目录初始化或克隆。
- Finder 操作打开相应的 MenuGit 窗口，包括提交、推送、拉取、分支、日志和冲突处理；不增加额外的主导航入口。
- 查看状态与统一差异、选择文件暂存、提交、拉取、推送、查看和切换分支、查看历史。
- 克隆仓库、初始化仓库，以及在应用内对比和解决冲突。
- 本机最近仓库、诊断信息、关于和手动检查更新。
- 系统 Git 配置、认证助手、SSH 配置和 Git hooks 的复用。

### 2.2 首发不做

- Windows / Linux 版本和其他文件管理器集成。
- Finder 文件图标状态角标。
- 一键放弃未提交修改。
- 交互式 rebase。
- stash、标签管理、`.gitignore` 管理、行级暂存、子模块管理、cherry-pick。
- 分支重命名或删除、提交历史分支图、图片差异预览。
- 强制推送、MenuGit 自有账号或凭证保存、Git 配置编辑界面、自动下载和安装更新。

## 3. 主要入口与页面

### 3.1 Finder 右键菜单

`MenuGit` 子菜单的仓库信息显示当前分支。嵌套仓库按距离右键目标最近的仓库作为操作对象。

| 右键位置 | 菜单内容与行为 |
| --- | --- |
| 仓库根目录、仓库内目录或文件 | 提交、推送、拉取、分支、日志；存在冲突时，通过相关操作返回冲突处理 |
| 仓库内单个或多个文件 | 提交页预选所选文件；提交和历史可带入文件上下文；拉取、推送、分支操作针对整个仓库 |
| 非仓库目录 | 在此初始化仓库、克隆仓库到此处 |

- 右键文件夹时，初始化目标为该文件夹；右键文件时目标为其所在目录；右键目录空白处时目标为当前目录。
- 只有目标不属于任何已有 Git 仓库时才提供初始化入口。
- 克隆默认在右键目录下新建以远端仓库命名的子目录；用户可调整名称或目标位置。
- Finder 扩展首次启用时提供系统设置引导。设置、诊断和关于入口位于应用内。

### 3.2 MenuGit 操作窗口

- Finder 右键选择操作后直接打开对应窗口；提交窗口展示变更、差异和提交信息，日志窗口展示历史，分支窗口管理分支。
- 从 Dock 启动且没有 Finder 仓库上下文时，提供最近 10 个仓库和“打开仓库”入口；最近列表保存在本机，可清除。该兜底入口的具体外观尚未在原型中展示。

## 4. 功能需求

### FR-01 Finder 集成与仓库发现

- 在仓库根目录、仓库内路径和非仓库目录提供 `MenuGit` 菜单。
- 从右键目标向上查找仓库；遇到嵌套仓库时采用最近的仓库根目录。
- 仓库菜单显示当前分支；拉取或合并发生冲突后进入冲突处理，右键菜单不单独增加“冲突”一行。
- 用户可在文件上右键或多选文件后进入提交页；文件级提交上下文预选所选文件。目录右键时默认只勾选该目录内已跟踪的更改，并显示操作范围；用户仍可调整勾选。
- 产品目标覆盖用户可访问的本地目录及已挂载磁盘；macOS 保护的系统目录不纳入承诺。该覆盖范围须通过技术验证后才能作为发布验收条件。
- 首次使用时说明如何在“系统设置 → 通用 → 登录项与扩展”中启用 Finder 扩展。

### FR-02 变更、差异与提交

- 变更页同时提供状态、文件列表、差异预览和提交输入。
- 按当前右键范围，修改、删除和重命名的已跟踪文件默认选中；新增/未跟踪文件默认不选中。显式右键选择的文件按选择范围预选，包括新增文件；用户可逐项调整或全选。
- 本次提交仅包含用户选中的文件。未选中的已暂存内容保留在暂存区，不混入本次提交。对同一文件既有已暂存又有未暂存修改时，勾选该文件提交当前工作区完整内容，并提示将包含未暂存修改；未选文件的暂存内容必须保留。
- 差异采用统一视图，以颜色区分新增和删除行。二进制或过大的差异不在应用内完整渲染，显示提示并可用默认应用打开。
- 提交信息必填，支持多行；首行过长时软提示，不阻止提交。长度提示阈值待定。
- 提交身份读取系统 Git 的 `user.name` 和 `user.email`。缺少身份时提示用户配置系统 Git，不提供 MenuGit 身份输入框。
- Git hooks 正常执行。hook 失败时保留改动，显示错误输出并允许重试；不提供跳过 hook 的按钮。
- 点击“提交”只创建本地提交，不自动推送。提交成功后立即打开独立的“推送”确认窗口，列出待推送提交和目标分支。
- 用户必须在推送窗口再次点击“推送”才会联系远端；选择“稍后推送”会关闭窗口并保留本地提交，之后可从 Finder 菜单的“推送”入口继续操作。
- 不提供一步完成的“提交并推送”按钮，以免跳过用户对推送目标和时机的确认。

### FR-03 拉取与推送

- 当前分支已有上游分支时，拉取和推送默认直接使用该上游。
- 没有上游时，显示本地分支和远端目标。推送默认目标为同名远端分支，若不存在则标注将新建；拉取只能选择已有远端分支。用户可选择其他已有远端分支，并选择是否记为当前分支的上游。MenuGit 只修改当前仓库的跟踪关系，不修改全局 Git 配置。
- 未配置远程仓库时，推送流程提供添加远端地址入口；仅修改当前仓库配置，不提供完整 Git 配置页面。新增远端前显示名称和地址并确认；拉取需要已有远端和已有分支。现有原型仍是旧提示，需要随实现更新。
- 拉取遵循当前 Git 配置的 merge / rebase 等策略；冲突处理中明确区分合并和变基，变基时标明正在重放的提交与变基基线。MenuGit 不额外启用自动暂存；用户已有的 Git 自动暂存配置如何生效须在真实环境验证（T-08），不得把原型示例中的阻止行为当作所有配置的规则。
- 推送失败时保留本地提交，明确说明“已提交到本地但未推送”，提供重试或拉取入口；不自动拉取，不提供强制推送。
- 已配置上游时不提供每次操作临时改选其他目标的入口。

### FR-04 分支

- 显示本地和远端分支，支持创建本地分支和切换分支；创建时若同名本地分支已存在，应提示用户直接切换，不覆盖原分支状态。
- 从远端分支检出时，建立同名本地跟踪分支。
- 有未提交修改时交由 Git 判断是否能安全切换；可能覆盖修改时阻止切换并说明原因。首发不自动 stash 或丢弃改动。
- 首发不支持分支重命名和删除。

### FR-05 历史

- 默认显示当前分支提交，按提交信息或作者搜索。
- 首屏加载最近 200 条记录，继续浏览时加载更早记录。
- 选择提交后显示涉及文件和差异；从文件右键进入时可按该文件查看历史。

### FR-06 冲突处理

- 拉取或合并产生冲突时，左侧列出可搜索、可多选的冲突文件及各文件未解决的冲突数；右侧聚焦所选文本文件的一处冲突，并展示本地、传入内容和合并结果。
- 提供上一处、下一处、下一处未解决和可关闭的选择后自动跳转；已解决的冲突仍可返回查看或修改。长内容显示行号，支持滚动、展开完整内容和查看相邻上下文。
- 文本文件支持逐个冲突块选择本地、传入或按顺序保留两边内容；该文件全部冲突块处理后标记为已解决。合并结果支持手动编辑并保存，保存前检查冲突标记；返回块选择前确认移除手动结果。复杂冲突类型和真实文件行号的实现方式待技术验证。
- 支持对勾选文件的未解决冲突块批量选择本地或传入，保留已选择的冲突块和冲突外内容；二进制文件不参与逐块操作。支持撤销最近的冲突处理，编辑中的结果须先保存或取消。
- 支持批量选择未解决文件并使用整份本地或整份传入版本；确认前明确显示文件范围，并说明会替换另一版本及此前的冲突选择，包括冲突以外的更改。已解决或未选文件不受影响。
- 所有文件解决后，用户必须明确点击“继续”或“中止”。“继续”调用 Git 当前 merge/rebase 操作的原生续行流程，提交信息由当前 Git 操作决定。
- 二进制冲突提供“保留本地版本”或“使用传入版本”的选择，不提供二进制内容差异视图。
- 中止前显示确认，说明中止将尝试恢复操作前状态，并提示冲突处理期间的编辑可能丢失；如果操作开始前就有未提交修改，不能保证所有修改都能恢复。
- 文本冲突支持应用内逐块选择；必要时可使用外部编辑器辅助处理。

### FR-07 初始化与克隆

- 初始化前显示目标路径供用户确认；目标位于已有仓库内时不提供初始化操作。
- 克隆支持 HTTPS 和 SSH 地址，使用系统凭证助手或 SSH 配置，不在 MenuGit 内输入或保存凭证。
- 克隆表单可调整目标目录和仓库文件夹名；操作期间显示进度并允许取消，目标路径已存在时明确提示并阻止操作。克隆完成后打开目标目录。

### FR-08 启动、偏好与更新

- 主应用支持从 Finder 上下文或 Dock 启动。
- 界面跟随 macOS 系统语言，首发支持中文和英文，不提供独立语言切换项。
- 仅保留必要的诊断和关于入口；更新由用户手动检查，不自动下载或安装。

### FR-09 错误与操作反馈

- Git 错误显示易懂的简要原因，并可展开和复制原始 Git 输出。
- Git 缺失或提交身份缺失时提供系统安装/配置指引，不自动安装或改写全局配置。
- 操作进度、成功结果和错误均显示在 MenuGit 中；不发系统通知、不播放提示音。

## 5. 配置、凭证与本机数据

- 复用系统 Git 的提交身份、credential helper、SSH agent、代理和 pull 策略。
- 不创建 MenuGit 账号，不保存独立凭证，不修改全局 Git 配置。
- 用户选择记住目标，或显式检出远程分支为本地跟踪分支时，可更新当前仓库的分支上游关系；不自动更改全局配置。用户确认后也可添加当前仓库的远端名称和地址。
- 最近仓库路径和诊断信息仅保存于本机；不发送遥测。诊断信息展示前遮蔽凭证，用户可查看或清除。

## 6. 分发与兼容性

- 通过直接下载的签名、公证 DMG 分发；首发不通过 Mac App Store。
- 首次使用提供 Finder 扩展启用指引。
- 构建 Apple Silicon 与 Intel Universal 应用；Intel 兼容范围不高于 macOS 26。
- 最低 macOS 版本依据 Finder 扩展、SwiftUI、Git 发现方式和其他依赖的验证结果确定。

## 7. 待确认与技术验证事项

| 编号 | 事项 | 当前决定 / 下一步 |
| --- | --- | --- |
| T-01 | Finder 扩展目录覆盖 | 产品目标已定为覆盖用户可访问的本地目录和已挂载磁盘；需验证广泛监控根目录及其后代是否稳定可用。Apple 文档说明菜单仅针对已监控目录及其后代，但未保证注册 `/` 一定可行。 |
| T-02 | Finder / 主应用文件访问权限 | 验证签名、公证的直接分发下，Finder 传入的目标路径与主应用对仓库文件的实际读写权限；目录注册本身不等于文件授权。 |
| T-03 | 最低 macOS 版本 | 通过 SwiftUI、Finder Sync 扩展和所选依赖的实际构建与运行验证后确定。 |
| T-04 | Universal 构建与 Intel 验收 | 验证主应用和 Finder Sync 扩展的 arm64 / x86_64 构建，并在目标 Intel/macOS 版本组合上验收。 |
| T-05 | 差异预览阈值 | “大文件不完整渲染”的大小/行数阈值在性能验证后确定。 |
| T-06 | 诊断日志轮换 | 诊断日志保留时长与文件大小上限待实现前确定。 |
| T-07 | 手动更新入口 | “检查更新”将打开的正式下载页地址待设置。 |
| T-08 | Git 配置与真实交互 | 验证系统 Git 的 pull 策略、自动暂存、凭证助手、SSH agent、交互式提示与 hooks；原型中的结果仅为模拟。 |
| T-09 | 提交与冲突安全 | 验证暂存区保留、特殊路径、并发更改、merge / rebase 多次冲突、二进制及删除/重命名等冲突；不能安全处理时保留现场并给出可恢复的替代路径。 |
| P-01 | 需求验证 | 当前定位和竞品差异基于产品意图，尚未通过目标用户访谈或竞品研究验证。 |
| D-01 | 同文件已暂存和未暂存修改 | 已确认选择当前工作区完整文件并提示；未选文件暂存内容必须保留。 |
| D-02 | 新仓库远端地址 | 已确认在推送流程中允许添加当前仓库远端；不更改全局配置。 |
| D-03 | 冲突编辑草稿 | 同次运行中关闭并重开保留草稿；正常退出时提醒先保存或放弃；意外退出时未保存草稿可能丢失，不得误称已保存到仓库。 |

## 8. 评审说明

- [PRD](PRD-MenuGit.md) 是概要，不重复定义详细业务规则；[开发方案](Development-Plan-MenuGit-macOS.md) 为待评审的实施提案。
- [旧版 PRD](archive/PRD-MenuGit-v0.4.md) 仅供历史参考；其中与本规格不同的内容不作为当前需求。
- D-01～D-03 已由用户确认，T 项须通过技术验证；本文不表示功能已实现或验收。
- 原型已演示主要页面，但 Dock 兜底、真实 Git 错误与认证、hooks、真实冲突状态、历史分页、Git 大文件性能及中英文完整覆盖尚未在原型中验证。冲突草稿仅为内存演示，不能证明退出后可恢复；这些是实现与验收工作，不作为改变首版范围的依据。
