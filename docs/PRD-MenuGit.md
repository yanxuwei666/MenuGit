## 1. 背景与目标

命令行 Git 对日常操作（提交、拉取、推送、切分支、看历史）有较高的记忆与心智负担；现有图形客户端要么仅支持单一平台，要么体量大、启动慢、概念多。Windows / macOS / Linux 三个桌面平台缺少一个统一且轻量的"在文件管理器里右键就能完成日常 Git 操作"的工具。

MenuGit 的产品响应：安装后集成进系统文件管理器（Windows 资源管理器、macOS Finder、Linux 文件管理器），所有功能收纳在右键"MenuGit"子菜单中；默认复用系统已有的 Git 配置与凭证，不做账号体系、不堆设置项。预期可观察结果：

- 用户安装后无需任何配置即可在右键菜单中使用全部 P0 功能。
- 完成"改动 → 提交 → 推送"一个完整循环全程不打开终端。
- 非仓库目录右键可初始化或克隆仓库，新用户可从零开始。

> **设计底线：不追求大而全。** 每个功能必须有明确的日常使用频率支撑；所有 Git 行为配置跟随系统 Git 配置，MenuGit 设置页只做兜底与排障。

## 2. 产品契约

| 要素 | 定义 |
| --- | --- |
| 主用户 | 在 Windows / macOS / Linux 桌面环境下做轻中度 Git 操作的开发者（独立开发者、学生、前后端工程师等）：会写代码，但不想为每次提交/拉取记忆命令，也不愿启动重型 GUI 客户端。 |
| 触发 | 用户在系统文件管理器中**右键点击**仓库内的目录 / 文件，或右键点击任意普通目录。 |
| 核心工作 | 不离开文件管理器完成：查看仓库状态与文件差异（提交窗口内置）、暂存并提交修改、拉取远端更新、推送本地提交、创建/切换分支、查看提交历史、放弃未提交修改、解决拉取冲突；以及在空目录初始化仓库、从 URL 克隆仓库；通过薄设置页调整少量自身行为。 |
| 完成标志 | 用户通过右键菜单完成一次"修改 → 提交 → 推送"循环且收到推送成功反馈，全程未打开终端；查看类操作以看到正确状态/历史为完成。 |
| 共享对象 | **Git 仓库（工作区）** 及其运行状态（当前分支、暂存区、变更文件、与上游的领先/落后）。 |
| 信任边界 | MenuGit 只读复用用户的 Git 配置与凭证，永不修改；破坏性操作（放弃修改、中止合并）必须显式确认；所有写操作有即时结果反馈。 |

## 3. 范围

### 3.1 最小完整旅程（P0）

```
右键仓库目录 → 提交窗口确认改动（状态+差异） → 填写信息提交 → 推送成功反馈
```

- **入口条件**：系统已安装文件管理器与 MenuGit；Git 操作要求系统已安装 git 命令。
- **完成证据**：推送结果反馈、提交窗口顶部"已同步"。
- **最重要失败的恢复路径**：拉取产生冲突 → 进入冲突处理（FM-08），可逐个解决后完成合并提交，或中止合并恢复到拉取前状态。

### 3.2 功能边界

| 层级 | 内容 |
| --- | --- |
| **P0 首发** | 右键菜单集成（FM-01）、提交（含状态与差异预览，FM-02）、拉取（FM-03）、推送（FM-04）、分支（FM-05）、日志（FM-06）、放弃修改（FM-07）、解决冲突（FM-08）、初始化仓库（FM-09）、克隆仓库（FM-10）、设置（FM-11）。 |
| **P1 后续** | 文件/目录状态角标（图标叠加）；KDE Dolphin、Nemo、Thunar 等更多文件管理器适配；暂存（stash）；分支重命名/删除；标签管理；忽略文件（.gitignore）管理；行级暂存（按 hunk 勾选）；日志分支图形线；图片差异对比。 |
| **明确不做** | 强制推送；交互式 rebase；cherry-pick；子模块管理；Git hook 管理；内置终端；多仓库批量管理；MenuGit 自有账号或凭证存储；设置页包含任何 git config 类配置。 |

"明确不做"用于对齐"轻量"的边界：以上能力交给专业客户端、命令行或系统 Git 配置，避免 MenuGit 概念膨胀。

## 4. 产品模型与菜单形态

### 4.1 菜单形态矩阵

右键菜单内容只由一个条件决定：右键目标是否位于某个 Git 仓库内（发现规则见 R1）。文件级右键复用同一组菜单，仅预置该文件的上下文。

| 右键目标 | 菜单内容 | 说明 |
| --- | --- | --- |
| 仓库内目录/文件 | 提交、拉取、推送、分支、日志、放弃修改、解决冲突 + 设置 | 操作作用于所属仓库根；文件级右键时提交窗口预选该文件、日志按该文件过滤 |
| 非仓库目录 | 在此初始化 Git 仓库、克隆仓库到此处 + 设置 | 入口操作，让新用户可从零开始 |
| 仓库内，但 git 命令不可用 | 同仓库菜单，点击任意项提示"未检测到 Git" | 提示含各平台安装指引，见 R2 |

菜单项规则：

- 任何时刻用户看到的菜单不超过 7+1 项（仓库内）或 2+1 项（非仓库）。
- "解决冲突"在仓库菜单中常驻，**无冲突时置灰**，存在冲突时高亮。
- "设置"位于分隔线之后的最底部，两个场景均可见。
- 只显示与当前场景相关的项，不显示灰色的不可用占位项（"解决冲突"除外，它承担冲突状态提示职责）。

### 4.2 菜单示意

```
仓库内右键 → MenuGit ▸                    非仓库右键 → MenuGit ▸
    提交…    ◄─ 主窗口：状态+差异+提交         在此初始化 Git 仓库
    拉取                                      克隆仓库到此处…
    推送                                  ─────────────
    分支…    ◄─ 创建 / 切换                   设置…
    日志…
    放弃修改…  ◄─ 二次确认
    解决冲突…   ◄─ 无冲突时置灰
─────────────
    设置…
```

### 4.3 主窗口（提交）示意

MenuGit 只有一个日常主窗口：打开即状态，点文件即差异，填信息即提交。

```
┌ 提交 · my-project ── 分支 main（领先 origin/main 1 个提交）─ ✕ ┐
│                                                              │
│  [×] 修改    src/app.py                          +24 −6      │
│  [×] 新增    src/utils.py                                    │
│  [×] 删除    docs/old.md                                     │
│  [ ] 未跟踪  notes.txt                                       │
│  ──────────────────────────────────────────────              │
│  （点击文件名，此处显示该文件的差异预览）                           │
│  ──────────────────────────────────────────────              │
│  提交信息（必填）…                                             │
│                                                              │
│  作者：yxw <yxw@example.com>（来自系统 Git 配置）  [取消] [提交 3 个文件] │
└──────────────────────────────────────────────────────────────┘
```

工作区干净时同一窗口显示空状态："工作区干净，与 origin/main 同步（或 领先 n / 落后 n）"。

## 5. 功能需求

### FM-01 右键菜单集成 `P0`

- **目的**：让用户在任何仓库路径下一步触达全部常用操作，无需打开应用。
- **触发**：用户在受支持的文件管理器（Windows 资源管理器、macOS Finder、Linux GNOME Files [Assumption, TBD：各平台首发顺序]）中右键点击文件或目录。
- **处理规则**：
  - 所有功能收纳在右键"MenuGit"子菜单中，形态见 4.1/4.2。
  - 按 R1 仓库发现规则决定展示"仓库菜单"还是"入口菜单"。
  - 仓库菜单顺序固定：提交 / 拉取 / 推送 / 分支 / 日志 / 放弃修改 / 解决冲突 / — / 设置。
  - 文件级右键：打开提交窗口时预勾选该文件；打开日志时按该文件过滤。
  - 子目录右键的操作作用于所属仓库根，窗口标题中展示仓库根路径与当前分支。
- **结果与状态变化**：点击菜单项打开对应窗口（FM-02、FM-05、FM-06、FM-07、FM-08、FM-09、FM-10、FM-11）或直接执行（拉取/推送，FM-03/FM-04）。
- **异常**：git 命令不可用时按 R2 处理；文件管理器扩展安装/启用失败时，安装器需给出重新启用指引。

### FM-02 提交（主窗口：状态 + 差异 + 提交） `P0`

- **目的**：把"看状态、看差异、提交"合成一个窗口，用户要学的只有一个界面。
- **触发**：仓库内右键 → "提交…"。
- **处理规则**：
  - 窗口内容见 4.3：顶部状态条（当前分支、上游、领先/落后提交数）、变更文件列表（勾选 = 暂存）、差异预览区（点击文件展开）、提交信息输入、作者信息展示。
  - 顶部分支徽章可点击，直接打开分支窗口（FM-05）切换或新建本地分支；提交始终落在当前分支上，"把改动放到新分支"应在提交前完成分支切换。
  - 变更文件按状态标记：`新增` `修改` `删除` `未跟踪` `冲突`，重命名显示"旧名 → 新名"；列表支持按文件名过滤。
  - 默认勾选规则：**修改、删除、重命名的文件默认勾选；新增/未跟踪文件默认不勾选**（防止误提交杂物）。"新增是否默认勾选"可在设置中反转（FM-11）。
  - **差异预览（共享视图，日志详情复用同一规格）**：位于文件列表右侧的固定预览区，点文件名即显示该文件 diff（左右两栏各自滚动）；只读、增/删行高亮；二进制文件显示元信息并提示"不支持内容对比"；文件编码异常时按字节展示并提示；文件过大时只加载前 N 行并提示 [Assumption, TBD：阈值]。
  - 提交信息必填；首行超过 50 字符时软提示（不阻止提交）。支持多行信息。
  - 作者身份直接取系统 Git 配置的 user.name / user.email 并在窗口展示；不在窗口内提供修改入口（提示用户修改系统 Git 配置，见 R2）。
  - 提交完成后窗口保留并刷新为新的变更列表，可直接继续下一次提交。
- **结果与状态变化**：产生一个本地提交；顶部计数变为"领先上游 n"；文件从未暂存/暂存区移除；随后**自动打开推送面板**（FM-04）。推送面板取消后：若工作区仍有未提交变更，返回提交窗口继续处理；若已全部提交，直接结束流程回到文件管理器，不再显示空提交窗口。
- **异常**：
  - 工作区干净：显示空状态（见 4.3），提交按钮禁用。
  - 未勾选任何文件或信息为空：提交按钮禁用并提示原因。
  - pre-commit 等 hook 执行失败：展示 hook 输出，本次提交不生效，用户可修改后重试。
  - 存在冲突文件：冲突文件不可勾选，顶部提示先处理冲突（FM-08）。

### FM-03 拉取 `P0`

- **目的**：把远端更新合入当前分支。
- **触发**：仓库内右键 → "拉取"，打开拉取对话框（与推送对话框同构：本地分支 + 来源远端/分支），确认后执行。
- **处理规则**：
  - 对话框默认来源为当前分支的上游，一次确认即完成；可改从其他远端分支拉取（下拉建议来自该远端已有分支）。
  - 执行期间显示进行中状态；遵循 R3 并发锁。
  - 当前分支无上游时：对话框同处选择来源分支，执行并记住上游设置（--set-upstream）。
  - 合并行为完全遵循用户系统 Git 配置中的 pull 策略，MenuGit 不额外干预。
  - 产生冲突时进入 FM-08 冲突处理。
- **结果与状态变化**：成功后显示摘要："拉入 n 个提交，更新 m 个文件"；无更新时显示"已是最新"。
- **异常**：认证失败 / 仓库不可达 / 网络错误：按 R5 呈现可读原因与原始输出，提供"重试"。

### FM-04 推送 `P0`

- **目的**：把本地提交发布到远端。
- **触发**：仓库内右键 → "推送"；或提交（FM-02）完成后自动打开。
- **处理规则**：
  - 推送打开轻量目标面板（参考 TortoiseGit 但极简）：默认目标为当前分支的上游，一次确认即完成；可改推到其他远端分支（下拉建议来自该远端已有分支）。
  - 目标输入新名称时在远端新建分支：明确提示"将创建远端分支 origin/&lt;name&gt; 并设为上游"后执行；无上游时同 FM-03 设置跟踪。
  - 推送面板只决定远端目标名称，不改变提交所属的本地分支；从提交窗口发起推送时，取消面板可无损返回提交窗口（勾选、过滤、提交信息均保留）。
  - **不提供强制推送**（见 3.2"明确不做"）。
- **结果与状态变化**：成功反馈"已推送到 origin/main"；领先计数归零；提交窗口顶部转为"已同步"。
- **异常**：推送被拒（远端有本地没有的提交）时提示"远端有新提交，请先拉取"，并提供"立即拉取"入口；认证/网络错误同 FM-03。

### FM-05 分支（创建 / 切换） `P0`

- **目的**：查看与切换本地分支，或从当前位置新建分支。
- **触发**：仓库内右键 → "分支…"。
- **处理规则**：
  - 窗口列出本地分支（当前分支置顶并标记"当前"），支持按名称过滤。
  - 折叠区展示远端分支；点击远端分支 = 检出为同名本地分支并建立跟踪。
  - 窗口内提供"新建分支"输入：基于当前 HEAD 创建并立即切换。
  - 切换时未提交修改的处理遵循 Git 原生行为：能携带则携带到目标分支；Git 报告会覆盖未提交修改时阻止切换，提示"请先提交或（P1）暂存修改"，并列出受影响文件。
- **结果与状态变化**：当前分支更新；提交窗口等后续界面同步刷新。
- **异常**：分支名非法（含空格/特殊字符）时即时校验提示；切换目标分支不存在时提示并刷新列表。

### FM-06 日志 `P0`

- **目的**：浏览提交历史并下钻到任意提交的变更。
- **触发**：仓库内右键 → "日志…"。
- **处理规则**：
  - 列表项展示：短 hash、信息首行、作者、相对时间、"HEAD / 本地分支 / 上游"标记。
  - 默认显示当前分支历史；提供"所有分支"开关。
  - 顶部过滤框按提交信息或作者实时过滤。
  - 点击提交展开详情：完整提交信息、变更文件列表；点击文件查看该提交的差异（复用 FM-02 的差异视图规格，对比对象为该提交与其父提交）。
  - 分页加载：默认加载最近 200 条，滚动到底自动追加 [Assumption, TBD]。分支图形线为 P1。
- **结果与状态变化**：只读。
- **异常**：空仓库（无任何提交）显示空状态："还没有提交，去完成第一次提交吧"。

### FM-07 放弃修改 `P0`

- **目的**：把改废了的未提交修改还原，是日常防呆兜底，避免用户为此打开终端。
- **触发**：仓库内右键 → "放弃修改…"。
- **处理规则**：
  - 窗口列出所有可放弃的变更：已跟踪文件的修改/删除（还原到 HEAD）与未跟踪文件（删除文件），每类用状态标记区分。
  - 支持全选或按文件勾选；默认不勾选任何文件，用户必须主动选择。
  - 按 R4 执行二次确认：确认框明确列出将影响的文件数，并写明"将永久丢弃这些修改，不可恢复"；未跟踪文件的删除需单独说明"文件将被彻底删除"。
- **结果与状态变化**：勾选文件还原或删除；列表刷新；受影响文件从变更列表消失。
- **异常**：工作区干净时点击菜单提示"没有可放弃的修改"；操作失败按 R5 呈现。

### FM-08 解决冲突（拉取后） `P0`

- **目的**：拉取产生冲突时，用最小的概念成本让用户安全走完合并，或安全退出。
- **触发**：FM-03 拉取产生冲突时自动弹出；也可通过仓库菜单"解决冲突…"进入（无冲突时置灰）。
- **处理规则**：
  - 冲突面板列出全部冲突文件（`冲突` 标记），并统计"已解决 / 总数"。
  - 点击文件进入**内置合并编辑器**（参考 TortoiseGit 的冲突编辑，简化为网页内嵌）：每个冲突块左右并列展示"你的（当前分支）"与"传入的（origin/分支）"两个版本，用户为每个冲突块三选一——**采用本地 / 采用远端 / 保留双方**；下方实时预览该文件的合并结果。
  - 一个文件的所有冲突块都做出选择后，该文件**自动标记为已解决**（已解决文件可"重新编辑"改选）；无需用户手工编辑冲突标记文本，全程不出现 `<<<<<<<` 等标记。
  - 全部文件解决后主按钮"完成合并提交"生效，提交信息自动生成（"Merge branch …"）。
  - 任意时刻可点击"中止合并"：按 R4 二次确认后恢复到拉取前状态。
  - 冲突未全部解决前，仓库处于 R3 写锁状态，其他写操作（提交/推送/切换/放弃修改）提示"请先完成或中止本次合并"。
  - [TBD] 更复杂的冲突（如需手动混合编辑双方内容）首版不支持，提示"请在命令行处理"并给出指引。
- **结果与状态变化**："完成合并提交"产生合并提交，冲突状态解除，菜单项回到置灰；"中止合并"回到拉取前的工作区与分支状态。
- **异常**：解决过程中再次拉取/推送被 R3 阻止；标记已解决后又有新冲突（极少数）时刷新面板并重新统计。

### FM-09 初始化仓库 `P0`

- **目的**：把任意本地目录变成 Git 仓库，是新用户的入口之一。
- **触发**：非仓库目录右键 → "在此初始化 Git 仓库"。
- **处理规则**：确认框展示目标目录名，确认后执行初始化；若系统 Git 配置缺少 user.name / user.email，提示"提交前请在系统 Git 配置中设置身份"并给出说明链接。
- **结果与状态变化**：成功后反馈"仓库已创建"，该目录右键菜单随即变为仓库菜单。
- **异常**：目标目录已是仓库（含位于仓库内部）时提示"此处已在仓库 xxx 中"，不执行。

### FM-10 克隆仓库 `P0`

- **目的**：从 URL 获取远端仓库到本地。
- **触发**：非仓库目录右键 → "克隆仓库到此处…"。
- **处理规则**：
  - 输入项：仓库 URL（必填，支持 https / ssh 形式）、目标文件夹名（默认取 URL 末段）、父目录（默认右键目录）。
  - 凭证完全走系统配置（credential helper / ssh-agent，见 R2），MenuGit 不询问、不保存账号密码。
  - 克隆过程中显示进行中状态；大仓库允许取消。
- **结果与状态变化**：成功后显示"克隆完成"，并提供"打开文件夹"按钮直达新目录。
- **异常**：目标文件夹已存在并非空 → 阻止并提示；认证失败 → 提示"请先在系统凭证/SSH 中配置访问权限"并展开原始输出；URL 无法解析 / 仓库不存在 / 网络错误 → 可读原因 + 重试。

### FM-11 设置 `P0`

- **目的**：为语言、排障提供兜底入口；保持概念负担为零，设置页永远不膨胀。
- **触发**：右键菜单 → 分隔线下"设置…"（仓库内与非仓库场景均可见）。
- **处理规则**：设置页只包含 4 项：
  | 设置项 | 说明 |
  | --- | --- |
  | 语言 | 跟随系统（默认）/ 中文 / English |
  | 新增文件默认是否勾选 | 反转 FM-02 的默认勾选规则（默认：不勾选） |
  | 打开诊断日志 | 查看运行日志与 git 检测结果，排障用 |
  | 关于 | 版本号、检查更新、项目主页 |
- **边界（不放进设置）**：用户名/邮箱、代理、凭证、默认编辑器、diff 工具等一切 git config 类配置——设置页只提供"如何在系统 Git 配置中修改"的指引链接，不做输入框（见 R2）。
- **结果与状态变化**：全部选项即时生效，保存在 MenuGit 自身偏好中（见 R2）。
- **异常**：无特殊异常；诊断日志目录不可写时提示原因。

## 6. 共享规则

- **R1 仓库发现**：从右键目标所在目录起向上逐级查找 `.git`；找到则进入"仓库菜单"，所有操作作用于该仓库根，窗口标题展示仓库根与当前分支；未找到则展示"入口菜单"（FM-09 / FM-10）。
- **R2 配置与凭证**：MenuGit 只读复用系统 Git 的全部配置（user.name/email、credential helper、ssh-agent、代理、pull 策略等），不修改用户任何 Git 配置，不存储账号凭证；自身仅保存 FM-11 中的设置项与界面偏好（窗口尺寸、最近过滤词）。git 命令不可用时：菜单仍可见，点击后提示"未检测到 Git"，并展示对应平台的安装指引 [Assumption, TBD：是否提供一键引导安装]。
- **R3 并发锁**：同一仓库同一时刻只允许一个写操作（提交 / 拉取 / 推送 / 切换分支 / 放弃修改 / 克隆写入 / 冲突解决提交）进行，后到的写操作提示"正在执行其他操作"；读操作（状态 / 差异 / 日志）随时可用。
- **R4 破坏性操作确认**：P0 中的破坏性操作是"放弃修改"（FM-07）与"中止合并"（FM-08）：确认框必须明确说明影响范围（哪些文件、什么后果）且需点击确认按钮生效。
- **R5 错误呈现**：所有 Git 报错统一转换为一句可读原因（如"远端拒绝了推送：远端有你没有的提交"），并提供"显示详细信息"展开 Git 原始输出，便于求助与排障。
- **R6 操作反馈**：写操作在触发窗口内即时反馈结果（成功摘要或错误），不弹系统级通知、不播放音效；进行中的操作在窗口与菜单处显示"进行中"状态。
- **R7 界面语言**：默认跟随系统语言，可在设置（FM-11）中固定为中文或英文；首发提供中文与英文。
